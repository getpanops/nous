# nous

Versioned, signed intelligence bundle for the [PanOps platform](https://github.com/getpanops/panops).

Provides weekly-updated security and operations content:

**Security:** SigmaHQ detection rules · YARA-Forge rulesets · Signature-Base · Emerging Threats
Suricata rules · MITRE ATT&CK Enterprise STIX · Elastic detection rules

**Operations:** kubernetes-mixin · node-exporter-mixin · etcd-mixin · awesome-prometheus-alerts ·
Pyrra SLO examples · OpenSLO examples · K8s runbooks

**PanOps-authored:** Custom Sigma/Falco/YARA rules · Grafana alert rules and dashboards ·
Pyrra SLO definitions

## Supply chain

Every bundle is:
- Built reproducibly in GitHub Actions
- Signed with [cosign](https://github.com/sigstore/cosign) keyless signing (Sigstore/Fulcio)
- Accompanied by an SPDX SBOM generated by [Syft](https://github.com/anchore/syft)
- Published as a signed OCI artifact on GHCR and a signed ZIP on GitHub Releases

See [VERIFICATION.md](VERIFICATION.md) for how to verify a bundle before applying.

## Delivery

| Mode | Source | Command |
|------|--------|---------|
| Online (OCI) | `ghcr.io/getpanops/nous:latest` | intel-updater CronJob (auto-verifies) |
| Airgap (tarball) | GitHub Releases | `cosign verify-blob` then `panops-update-intel apply` |
| Airgap (OCI mirror) | Internal registry via `crane copy` | intel-updater with `INTEL_REGISTRY` override |

## Updating sources

Intel sources are pinned in [sources.yaml](sources.yaml). Renovate opens PRs automatically
when upstream projects publish new releases.

## Structure

```
rules/          PanOps-authored detection rules (Sigma, Falco, YARA, Pyrra SLOs)
grafana/        Grafana alert rules and dashboards
updater/        intel-updater image source (Dockerfile + panops-update-intel.py)
sources.yaml    Full catalog of upstream intel sources with Renovate pins
.github/
  workflows/
    build-bundle.yaml    Weekly build: download → pack → sign → push to GHCR
    validate-rules.yaml  PR check: Sigma syntax, YARA compile, YAML parse
renovate.json   Renovate config for upstream source version tracking
VERIFICATION.md How to verify a bundle before trusting it
```
